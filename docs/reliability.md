## ① 静态层：真实绘图代码语料验证（10,158 份）

本节是**用真实绘图代码跑出来的静态验证**。语料是 **10,158 份 sha256 唯一**的公开绘图脚本，来自真实项目：**Zenodo 数据集记录 6904 份**、
**GitHub 上的科研绘图仓库 2045 份**、若干项目的**官方 gallery 1209 份** —— 其中大量脚本是**不同论文的补充材料**。
实测只做**静态**定位与改写判定（**不执行**语料脚本，也**不再分发**）；**逐脚本的 URL / 许可 / sha256 在
[`bench/manifest.jsonl`](https://github.com/shdbl/mpltweak/blob/bench/bench/manifest.jsonl)，
脚手架与逐脚本结论在 [`bench` 分支](https://github.com/shdbl/mpltweak/tree/bench)**（判定文件已脱敏：只保留判定字段，不含脚本正文）。其中 **4,427 份**是绘图脚本（可静态分析 2,396 / 无图 1,940 / 语法错 90 /
1 份隔离重扫仍超时）（口径：**0.1.9 静态研究**按"可分析性"分层得到的 4,427 份；**0.1.10** 的静态筛选普查按清单里的 `plot==true` 记为 **4,433 份** —— 两者是**不同管线**，后者用于挑真跑候选池，其 `both_ok` = **1,837** 即 ② 的池），下表的分母都来自这些脚本里的**可测站点**。

### 语料怎么来的（可复核）

| 来源 | 份数（`manifest.jsonl` 实测） |
|---|---:|
| Zenodo 数据集记录（论文补充材料里的 `.py`） | **6,904** |
| GitHub 科研绘图仓库（61 个仓库名） | **2,045** |
| 官方 / 项目自带 gallery | **1,209** |
| **合计** | **10,158** |

筛选与去重口径：**只要 `.py`，并按 sha256 唯一化**（同一份脚本在多处出现只留一份）——
合并阶段原始记录 **10,168** 份，sha256 唯一化后 **10,158** 份（丢 10 份完全相同的重复；
本地构建日志（`corpus_union/_logs/build_summary.json`，未随仓库发布）记为 `copied=10168 / unique_sha=10158`，
`sha_mismatch=0 / size_mismatch=0 / undecodable=0`）；更早一次跨阶段合并另有
**`dup_cross_stage = 1469`** 条命中同一 sha 的记录被跳过（同一脚本在 GitHub / Zenodo 两个阶段都抓到）。
**语料本体保存在本地只读、不再分发**，仅公开清单（`manifest.jsonl`：路径 / 来源 / URL / 许可 /
sha256 / 大小）与**脱敏后的逐脚本判定**；想复核某个脚本被怎么判的，用清单里的 `sha256` / `url`
自行取回原文即可。全部材料在 [`bench` 分支](https://github.com/shdbl/mpltweak/tree/bench)：`manifest.jsonl`、
`verdicts/*.jsonl`（逐脚本判定）、`harness/`（脚手架）、`tools/`（两张表的生成脚本 + 脱敏自检脚本）。

### 原位修改（直接改源码里的数字）

| 可调项 | 该族有站点的脚本 | 可原位到达的脚本 | 真原位写回（组合） | 通过率 |
|---|---:|---:|---:|---:|
| 画布尺寸 `figsize` | 2,256 | 2,256 | 2,247 | **99.6%** |
| 面板位置 `pos` | 131 | 94 | 93 | 98.9% |
| 标题字号 | 193 | 173 | 165 | 95.4% |
| 轴标签字号 x | 181 | 173 | 160 | 92.5% |
| 轴标签字号 y | 180 | 171 | 166 | 97.1% |
| 刻度字号 x | 189 | 91 | 85 | 93.4% |
| 刻度字号 y | 6 | 5 | 4 | 样本不足（n=5） |
| 网格 `grid` | 131 | 124 | 118 | 95.2% |
| 轴范围 `xlim` | 401 | 247 | 232 | 93.9% |
| 轴范围 `ylim` | 433 | 276 | 261 | 94.6% |
| **合计** | **4,101** | **3,610** | **3,531** | **97.8%** |

- **通过率 = 真原位写回 ÷ 可原位到达**（不是 ÷"源码里有这一项"）。
- **合计是各族的和**，同一脚本的不同族会各计一次，**不等于脚本数**。
- **承诺违约 = 0**：没有任何一行出现"工具声称原位写回、字节却没变"（这批语料判定的范围内）。
- 没走成原位的分三类，逐脚本清单在 [`bench` 分支](https://github.com/shdbl/mpltweak/tree/bench)：**参数非法被拒 37** ·
  **证不出目标对象而拒绝落地 7** · **改为追加块完成 3**（都不是静默丢改动）。

### 追加代码块（原位表达不了的改动）

有些排版项在源码里**没有可替换的字面量**：典型是 `plt.subplots()` 网格轴的位置，以及
`spines`（边框）、`xscale` / `yscale`（轴类型）、`clim`（色标范围）。这类项**改不了数字**，
mpltweak 的做法是：在目标对象**创建之后、被消费之前**（最后一个 `savefig` / `show` 之前）
追加一段**自包含的调整块**，块首尾各有一行显式标记（`# ===== auto layout (generated) ...` /
`# ===== end auto layout =====`），`revert` 可以整块移除。

这一节验证的就是**这些块到底可不可靠**：

| 判据 | 含义 | 全库（分母 = 走了块通道的脚本） |
|---|---|---|
| 块数 | 静态扫描里**真的插入了调整块**的脚本数 | **427** |
| 原文逐字节保留 | 块**以外**的原文一个字节不变（含行尾） | **427 / 427** |
| 不用运行期定位 | 块内不出现 `fig.axes[i]` / `plt.gca()` / `plt.gcf()` 这类**运行时才知道指向谁**的写法 | **427 / 427** |
| 作用到目标对象 | 块里的目标表达式**静态可证**（用变量名，或可枚举的 `plt.figure(n).axes[k]`） | **427 / 427** |
| 幂等 / 可撤销 | 再写一次不会重复插入；`revert` 能回到原件 | √ |

- **427 是"块通道的规模"**（脚本级）：全库 4,427 份绘图脚本里，有 427 份的改动走了插入块这条路。
  它**不是**下面那个 **3**（"本来能原位、工具却退了块"）—— 那个是**组合级**的能力缺口计数，两者口径不同。
- **没有**对 427 个块做逐族拆分（即：多少块来自网格轴位置、多少来自 `spines` 等），报告里只给总量与判据通过率。
- 块通道**不参与第一张表（原位）的分母**：这套扫描的原位判定只覆盖那 10 个族；上面这些只能插块的项，
  **只在这一节里被验证**。

### 没到 100% 的那部分是什么

| 族 | 真原位 | 改为块落地 | 证不出而拒绝 | 参数非法被拒 | 记录缺条目 |
|---|---:|---:|---:|---:|---:|
| `figsize` | 2,247 | 0 | 0 | 0 | 9 |
| `pos` | 93 | 0 | 0 | 0 | 1 |
| 标题字号 | 165 | 1 | 0 | 1 | 6 |
| 轴标签字号 x | 160 | 0 | 1 | 11 | 1 |
| 轴标签字号 y | 166 | 0 | 1 | 0 | 4 |
| 刻度字号 x | 85 | 2 | 3 | 1 | 0 |
| 刻度字号 y | 4 | 0 | 1 | 0 | 0 |
| `grid` | 118 | 0 | 1 | 3 | 2 |
| `xlim` | 232 | 0 | 0 | 9 | 6 |
| `ylim` | 261 | 0 | 0 | 12 | 3 |
| **合计** | **3,531** | **3** | **7** | **37** | **32** |

上表是**完全划分**：每族的五类之和 = 该族"可原位到达"（10 族合计 **3,531 + 3 + 7 + 37 + 32 = 3,610**），
逐族逐类都由 `bench` 分支的 `verdicts/scan_full.jsonl` 复算得到（复算脚本与断言见下）。

- **改为块落地（3 例）不是失败**：改动落地了，只是走了追加块那条路。
- **证不出而拒绝（7 例）是刻意的**：静态判不出"改的是哪张图 / 哪条轴"就**不写盘**（`applied=false`、`pending` 非空），
  并打印可粘贴的手改片段。
- **参数非法被拒（37 例）**：测量脚手架按站点推出的参数越过了工具校验器的合法边界（例：轴序号越界、同图重名轴），
  工具拒绝是正确行为。**若把这 37 例从分母剔除，轴标签 x 的通过率是 160/161 ≈ 99.4%** ——
  这种剔法必须写明口径，所以两个数都列出来。
- **记录缺条目（32 例）是**流水线的**记录缺口，不是产品行为**：这些组合在 `n_reach_sites` 里被判可达，
  但原始判定记录里**根本没有该族的条目**（`families` 里连键都没有），所以既不能说它原位成功、也不能说它被跳过。
  取证（2026-10-13）：`bench/verdicts/scan_full.jsonl` 共 4,427 行（与 4,427 份绘图脚本一一对应，
  **无重复 path**）；全库 `families` 条目共 **3,578** 条，比可达组合 3,610 少**正好这 32 条**；
  这 32 条分布在 **25 个脚本 / 8 个族**（`figsize` 9 · `xlim` 6 · `标题字号` 6 · `标签y` 4 · `ylim` 3 · `grid` 2 · `标签x` 1 · `pos` 1），
  且它们的脚本 `error` 全为 `null`（可分析）、其它族有正常条目。**排除两种可能**：① 不是"按 path 去重丢明细"
  （4,427 行 = 4,427 个唯一 path，每个 path 只出现一次）；② 不是脱敏造成的（`tools/sanitize_verdicts.py` 是纯白名单投影，
  `families` 的键**只增不减**）⇒ 缺口发生在上游静态扫描：那 32 个可达组合没有被写判定条目。
- **旧表述与本文的对齐（重要）**：`bench/tools/_cu_why_not100.py` 那份"为什么没到 100%"报表统计的是**有判定条目的
  3,578 个组合**，所以它的四类之和是 3,578（= 3,531 + 3 + 7 + 37），**与主表的 3,610 不同源**：差的正是这 32 条记录缺口。
  本文件现在两处都用**同一口径**（主表的 10 族 / 可达 3,610），上表五类之和因此等于 3,610。

> 判定口径：全部为**静态层**（只做 AST 定位与改写判定，不执行语料脚本）。汇总结论：**97.8% 的改动原位落进源码（3,531 / 3,610），且没有一次"声称改了却没改"。**

## ② 运行时层：写回后重跑验证（0.1.10）

**为什么单独有这一层**：静态层证明的是"改得对"，运行时层证明的是"改完这张图还画得出来" ——
两者的分母不一样，结论也不一样，所以分开报。

**口径**：对能真跑的绘图脚本，用 `apply --write` 走完整链路（写盘 → **重跑脚本** → 把目标图状态与参数逐字段比对）。
范围写进句子：**池 1,837 份**（含 28 份"真会开窗" + 29 份"联网 / 子进程"的**静态排除**）⇒ **真跑候选 1,780 份**。

| 测什么 | 规模 | 结果 |
|---|---|---|
| 真实脚本真跑（写回 + 重跑 + 状态比对） | 池 1,837 → 真跑候选 1,780 | **928 份写回并验证通过**；其余因脚本需开窗（345）／等人输入（464）／联网或子进程（29）／撞 90 s 超时（71）**未判定**（`na_reject` / `na_error` = 0 / 0） |
| 四条铁律（幂等 / 可逆 / 语法守恒 / 只动目标） | 928 份 × 4 律 | **3,712 / 3,712**（逐律各 **928 / 928**） |
| 写回不篡改（"说没写就一个字节都不能变"） | 1,837 份 | **违约 0**（其中 928 份被真正写回：没有任何一份"声称写了、字节却没变"；`na_reject = 0`，故"拒写不改字节"这条判据无对象） |
| 语料目录完整性 | 跑前 / 跑后快照 | **未被修改**（前后快照相等）；runner `EXIT=0`；坏 JSON **0** |
| 耗时 | 首份 → 末份 | **53.5 分钟**（口径：首份 → 末份结果的**计算耗时**；并发档位在运行中按**内存动作线**调整过，分三段跑完：seg1 `jobs=6` 754 份 → seg2 `jobs=8` 601 份 → seg3 `jobs=6` 482 份，段间为干净停手 + `--resume`；份数与档位出处 `SUMMARY.md:287`） |

- 这套判据与离屏侧的 property 测试（`tests/test_property_writeback.py`）用的是**同一批断言**，
  所以"离屏绿"与"语料绿"可以互相印证，而不是两套口径。
- 重跑失败会**分归因**报（"你的脚本跑不起来" vs "工具改坏了"），见 [troubleshooting.md](troubleshooting.md) ③；
  脚本跑不起来时**不保留**这次写回（默认回滚），拒写就**一个字节都不动**。

## 附：验证是怎么设计的

主 README 只留结论，**设计细节都在这一节**。

### 1. 四层证据，各回答一个问题

| 证据 | 分母 | 它回答什么问题 |
|---|---|---|
| 静态语料（**不执行**脚本） | 10,158 份（其中 4,427 份是绘图脚本） | **“找不找得到、改不改得动”真实代码里的目标数字** |
| 运行时真跑（**真执行**） | 池 1,837 → 真跑候选 1,780 | **“改完之后还能不能跑、图的状态对不对”** |
| 四条铁律（幂等 / 可逆 / 语法守恒 / 只动目标） | 同一批真跑脚本 | **“会不会改坏”** |
| 窗口交互（离屏矩阵 + 真窗口） | 12×1,000（实跑 13,000）+ 6×1,000 | **“交互在各种图形与屏幕环境下稳不稳”** |

一层只回答一个问题：静态层证明“改得对”，运行时层证明“改完还画得出来”，铁律证明“不会改坏”，
交互层证明“几何与手感在各种图形、各种屏幕环境下都成立”。

### 2. 窗口交互的设计

**先定义两层**（后文所有数字都落在这两层里）：

- **A 层（随机操作）**：每种图形 1,000 次随机手势，**每一次操作后**校验 4 条不变量（不崩 / 往返一致 / 几何合法 / 落位与参数一致）⇒ **失败 0**。
- **C 层（定向场景）**：**27 条**确定性硬断言，每条都有明确对错（超屏长宽比守恒、高分屏裁白边一致性、拖拽落位精度、框选 / Ctrl 多选 / 清空、吸附残差、撤销重做往返、两种后端 …）⇒ **全过**。

**两种打法（随机 + 定向）**

- **A 层 · 随机**：每种图形 **1,000 次随机手势**，动作从 **7 类**里抽：拖拽移动 / 拉角拉边 / 图例拖动 /
  框选 / Ctrl 点选 / 键盘（含 `Ctrl+Z` / `Ctrl+Y`）/ 方向键；并**刻意混入 4 种乱序形态**：没按就拖、
  按了不松、拖到画布外、中途撤销。
  **为什么随机层只断言不变量**（而不是“某次操作应该产生什么”）：**随机操作没有“预期结果”** —— 只能断言与具体动作无关的
  不变量（轴数不变、每轴图元数不变、几何合法、图例/总标题不丢）。
- **C 层 · 定向**：**27 条硬断言**，每条都有明确对错（A1–A2 + B1–B6 + C1~C4 / C6~C10 + C11~C20）：
  超屏长宽比守恒、高分屏裁白边一致性、拖拽落位精度、框选 / Ctrl 多选 / 清空、吸附残差、
  撤销重做往返、两种后端。

**6 种图形为什么是这 6 种**（每种压一个不同的失败面）

| 图形 | 压什么 |
|---|---|
| 2×2（最典型） | 常规多面板，基线 |
| **4×4 = 16 面板** | 规模压力：最贵 —— 实测 **1.25 s/手势** |
| **GridSpec 不规则**（跨行跨列 + 非等分比例） | 定位最难 |
| 主面板 + 独立 colorbar 轴 | 特殊轴，最容易被误伤 |
| constrained_layout 2×2 | 布局引擎会与手动位置相互覆盖 |
| 1×3 横排 + tight_layout（带长中文标题） | 长宽比极端、标题容易被裁 |

**判据三档（为什么这样分）**

| 档 | 用在什么上 | 失败怎么处理 |
|---|---|---|
| **硬断言** | 不放宽的口径：长宽比偏差 ≤2%、位移误差 ≤0.02、多选同位移 … | 直接判失败 |
| **宽容断言** | 位置类：范围 / 相对位移 + 容差（禁止精确等值） | **自动重试 1 次**再判 |
| **软检查** | 只记录：操作生效率、是否抢焦点 … | 只记录，不判失败 |

理由：**假红的真正来源是“断言依赖环境细节”**（像素被 int 截断、浮点 `fig.bbox`、窗口管理器钳制），
不是产品行为 —— 所以按“这条断言会不会被环境细节影响”分档，而不是一刀切放宽。

**两种后端为什么都要验**：没装 PyQt5 的用户会走 **Tk 回退路径**（0.1.9 决策 B），
而两个后端的**坐标单位与 DPI 口径不同**（Tk 报物理 px、Qt 报逻辑 px），必须各自验证 ——


**“干净运行”纪律（数字只能来自干净运行）**：反污染采样 —— 每 10 次手势 + 每次读数都采样
`isActiveWindow`，疑似被抢焦点就打印 `★ WARN` 并**自动重跑该场景一次**；另打印一行
**机器负载自检**（其它 python 进程数 + CPU 基准 ms，只读、不作判据）。

**耗时规律（窗口批次终值，值得记住）**：每手势耗时随**轴数**单调上升 —— 2 轴 **0.213 s** /
3 轴 **0.327 s** / 4 轴 **0.373~0.422 s** / 16 轴 **1.241 s**。⇒ 成本主因是**轴的几何处理 + 重绘**，
不是等待（`pump×0.25` 把等待压到 1/4，4 轴版面仍 0.37 s/手势）。与离屏矩阵 4×4 的 **1.118 s/操作**
互相印证（窗口侧 1.241 s/手势，同量级）。

> **出处（终值）**：Qt 逐类 fuzz 实测 —— monkey **421.9 s** / grid4x4 **1241.2 s** / gridspec **373.2 s** /
> colorbar **213.2 s** / clayout **372.5 s** / tight1x3 **326.5 s**，合计 **2948.5 s ≈ 49.1 min**
> （`run_qt9.log:20,27`；逐行清单 `NUMBERS.md:130-131`）；Tk 轮墙钟 **7.8 s**（`run_tk7.log:30`；`NUMBERS.md:32`）。

### 3. 离屏 vs 真窗口：分工，不是互相替代

| | 负责什么 | 能照到什么 |
|---|---|---|
| **离屏矩阵**（不开窗、便宜、确定、可进 CI） | **广度**：12 种图形 × 1,000 次 = 口径 12,000（⑫“多 figure 脚本”含两张子图各 1,000 ⇒ **实跑 13,000**） | 图形与操作种类的广度、几何不变量、两种控制台编码 |
| **真窗口**（需要真实显示器） | **环境真实性**：6 种图形 × 1,000 = **6,000** 次手势 + 27 条硬断言 | 高分屏（dpr=2）、窗口管理器钳制、两种后端、焦点/打扰行为 |

这是**设计意图**（各自能照到什么），不是免责声明：离屏能穷举广度但照不到真实窗口环境；真窗口照得到环境但跑不起上千次。

### 4. 代码写回的设计

静态（只判定、**不执行**）→ 运行时（**真跑** + 语义比对“目标图状态 == 参数”）→ **四条铁律**
（幂等 / 可逆 / 语法守恒 / 只动目标）。一条硬不变量：**拒写必须 0 字节改动**（任何一层不过就回滚，
源码保持批前状态）。陌生语料跑在**沙箱**里 —— 给脚本一个封闭游乐场：**cwd 隔离 + 审计钩子 + 禁 GUI + 静态预筛**。

### 5. 设计取舍

- 离屏每种图形分 **2 段各 500 次**（跑在两个**独立**的新 figure 上）⇒ **损失“单条 1,000 步连续游走”的覆盖**
  —— 这是换取整套约 7 分钟跑完的代价（连续游走能压到“长序列状态漂移”这类问题）。
- 真窗口套件**不进 CI**（会开窗、会短暂抢焦点），只能在放行时人工跑。
