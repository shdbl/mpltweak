# 边界与口径（专家向）

> 这份文件只回答一个问题：**mpltweak 什么时候不管用、它不声称什么。**
> 第一次用**不用读**：先按 [README](../README.md) 的「5 分钟上手」走一遍，卡住了看 [troubleshooting.md](troubleshooting.md)（三个最常见的问题）。
> 下面每一条都是**限制**（能力边界与实际测到的口径），不是"下一步计划"；带数字的地方都写明分母与口径来源。

## 一、不适用场景（先说清楚）

写回验证要在**你的机器上、用你的环境把整个脚本重跑一遍** —— 这是机制的一部分，不是可选步骤
（`--no-verify` 能跳过，但那等于关掉唯一的安全网）。所以下面这些脚本它帮不上忙：

| 脚本特征 | 为什么 |
|---|---|
| 要读大数据 / 依赖重环境 / 要联网或凭据 | 无头重跑会卡住或失败 |
| 中途需要人工输入（`input()`、交互式选择） | 无头重跑直接堵死 |
| 需要在特定交互后端才有意义的图 | 验证固定用 Agg 无头后端 |

**跑得久不算"不适用"**：脚本慢只意味着这次写回**等得久一点**，机制上没有任何一条会因为脚本慢就不成立
（单次重跑的默认超时是 300 秒，`--timeout` 可放宽；超时不会被判成写坏 —— 保留写回并提示手动确认）。
遍数与超时口径见 [verify.md 的「写回会跑几遍脚本」](verify.md#写回会跑几遍脚本)。

这类脚本走只读路线（`mpltweak describe` / `mpltweak check`，都不跑写回），或者手动改代码。
它的目标用户是**本地跑得动的小中型科研绘图脚本**。
（上表与 README「你这个脚本能帮上吗？两个问题」一节同口径；改一处要两处一起改。）

## 二、执行边界：哪些命令会跑你的脚本

**它不是一个沙箱**：`describe` / `check` / 开窗会**执行**你的脚本（在**子进程**里、Agg 无头，退出码与全局状态留在子进程内）；`apply` 只做 AST 改写，除非你要求**重跑验证**（`--write` 后默认重跑一次，`--verify-fast` 只做 `ast.parse`）。

**同一个脚本会被重复执行**：开窗 1 次、每次 `check` / `describe` 1 次、每次 `apply --write` 1 次 ——
所以别把它指向"跑一次会花钱 / 会改数据 / 会发消息"的脚本。

逐命令的实测表（每条都标"会不会跑脚本"）、工具自己的副作用（写哪些文件、写在哪、联不联网、
cwd / `sys.path` / 全局 `rcParams` 怎么处理）见 [exec-boundaries.md](exec-boundaries.md)。

## 三、退出码（口径）

`0` 成功（含"没发现问题""未检测到改动"）；`1` **跑通了，但结果需要处理**；`2` **输入 / 用法错误**（子命令层）；
`3` **顶层路径**（`mpltweak <脚本>` 这条入口）的问题；`4` **开窗但找不到可用图形后端**。

两点容易踩：**脚本自己的 `sys.exit(N)` 不会成为命令的退出码**（执行在子进程里）；
**"脚本找不到"在顶层是 3、在子命令是 2**（口径未统一）。

完整实测表（每个码配实测例子，并写明"只列实测过的组合"）见 [exec-boundaries.md](exec-boundaries.md) 的「退出码（实测）」。

## 四、验证能证明什么、不能证明什么

三层（语法 / 重跑 / 语义）各查什么、`--json` 里的 `layers` 怎么读，见 [verify.md](verify.md)。这里只列**不声称项**：

- **语义层有"不判"的字段**：判不了时 `verified=null`，并把字段列进 `--json` 的 `detail` 的「未判定字段」清单 ——
  这与"没比却说通过"相反，**会显式说出来**。逐条字段清单与原因见 [CHANGELOG](../CHANGELOG.md) 的「已知边界（本版不声称的）」。
- **明确拒绝是能力边界，不是失败**：目标对象静态证不出时（未命名 colorbar 轴、循环里建图 / 建轴、`fig.axes[i]` 这类运行期定位）
  不写盘、不插块（`applied=false`、`pending` 非空），并打印可粘贴的手改片段。静态语料全库 **4,427** 份绘图脚本里（0.1.9 静态研究口径；0.1.10 静态筛选普查按 `plot==true` 为 **4,433**），
  这类拒绝（含 fail-closed）共 **7** 例。
- **`--verify-fast` 不是"弱一点的重跑"**：它只做 `ast.parse` —— 不重跑脚本、也不证明布局落到了目标图上
  （JSON 里标 `verify_mode: "fast"`、`verified: null`，人读输出也会自己说明）。
- **`--keep-unverified` 是自担风险的档位**：脚本在无头环境跑不通（缺数据 / 依赖 / 需要 GUI）时**默认不保留**这次写回；
  加了它才保留，此时 `verified: null` + 警告，**要自己跑一遍确认**。
- **备份的可逆范围要按作用域看**：`apply --write` 会让脚本旁的 `.tweak_params/` 里同时存在**两份**可回退的备份
  —— ① **固定名** `<脚本>.tweak.bak`（默认 `revert` 用）**首份优先**：只在不存在时创建，之后的写回**不覆盖**它
  ⇒ 回到的是它**建立那一刻**的原文，通常就是你**第一次改这张图之前**的原件（实测：独立进程连续 3 次写回后
  `revert --write` 回到最初原件，不是上一步的中间态）；
  ② **带 pid 的专属副本** `<脚本>.tweak.<pid>.bak`（`revert --first` 用）代表**该次写回之前**，每次写回都新增；
  （首次写回时两份同时建立；之后每次只新增 pid 副本、固定名那份保持不动。）
  `_prune_backups` 保留"最近 5 份 + **最早 1 份**"（裁掉的是**中间**的）⇒ 连续写回很多次后 `--first`
  仍能回到最早那次写回之前；副本写不出来时（典型是 Windows 长路径）`--first` **明确失败 `rc=2`**，
  不会拿固定名备份冒充"最早"。
  备份**恒定落在脚本旁**（`<脚本目录>/.tweak_params/`，锚点是脚本而不是参数文件）⇒ `revert` **不需要**
  传 `--params`。`revert` 自身可逆：覆盖前另存 `<脚本>.revert.bak`。

## 五、语料验证的口径（分母怎么算）

[reliability.md](reliability.md) 的「① 静态层：真实绘图代码语料验证」三条口径，抄在这里以免只看结论：

- **只做静态层**：只做 AST 定位与改写判定，**不执行**语料脚本，也**不再分发**语料本体。
- **通过率 = 真原位写回 ÷ 可原位到达**，不是 ÷ "源码里有这一项"。
- **合计是各族之和，不等于脚本数**（同一脚本的不同族各计一次）。

汇总结论是 **97.8%（3,531 / 3,610）**，且**承诺违约 = 0**（没有任何一行"声称原位写回、字节却没变"）。
逐脚本的 URL / 许可 / sha256 与脱敏判定在 [bench 分支](https://github.com/shdbl/mpltweak/tree/bench)。
