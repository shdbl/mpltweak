# 边界与口径（专家向）

> 这份文件只回答一个问题：**mpltweak 什么时候不管用、它不声称什么。**
> 第一次用**不用读**：先按 [README](../README.md) 的「5 分钟上手」走一遍，卡住了看 [troubleshooting.md](troubleshooting.md)（三个最常见的问题）。
> 下面每一条都是**限制**（能力边界与实际测到的口径），不是"下一步计划"；带数字的地方都写明分母与口径来源。

## 一、不适用场景（先说清楚）

**先回答两个问题**：

1. **你的脚本能不能"没人管"地自己跑完？** 不用你点、不用你输、不靠屏幕上的窗口 —— 写回时的验证会在**无头环境**里**真的跑你的脚本**，旁边没有人在帮它。
2. **要联网、要输密码、要读很大的文件吗？** 有就别用写回。

两个都过得去，它多半帮得上。**真正的门槛只有一条：能不能在无头环境里无人值守跑通** —— 写回验证要在**你的机器上、用你的环境把整个脚本重跑一遍**，这是机制的一部分，不是可选步骤
（`--no-verify` 能跳过，但那等于关掉唯一的安全网）。所以下面这些脚本它帮不上忙：

| 脚本特征 | 为什么 |
|---|---|
| 要读大数据 / 依赖重环境 / 要联网或凭据 | 无头重跑会卡住或失败 |
| 中途需要人工输入（`input()`、交互式选择） | 无头重跑直接堵死 |
| 需要在特定交互后端才有意义的图 | 验证**默认** Agg 无头，但没"钉死"：重跑层只设 `MPLBACKEND=Agg` 就裸跑子进程（`writeback.py:7164 # MPLBACKEND` 设 env、`writeback.py:7167 # cmd` 裸跑），脚本自己写 `matplotlib.use('TkAgg')` 能顶回去 ⇒ 无头机器上跑不通、有桌面的机器上可能真弹窗（采集 / 语义层另把后端钉成 Agg：verify.py:875 # matplotlib.use） |

**跑得久不算"不适用"**：脚本慢只意味着这次写回**等得久一点**，机制上没有任何一条会因为脚本慢就不成立
（单次重跑的默认超时是 300 秒，`--timeout` 可放宽；超时不会被判成写坏 —— 保留写回并提示手动确认）。
遍数与超时口径见 [verify.md 的「写回会跑几遍脚本」](verify.md#写回会跑几遍脚本)。

这类脚本走只读路线（`mpltweak describe` / `mpltweak check`，都不跑写回），或者手动改代码。
它的目标用户是**本地跑得动的小中型科研绘图脚本**。

## 二、执行边界：哪些命令会跑你的脚本

**它不是一个沙箱**：`describe` / `check` 会**执行**你的脚本（在**子进程**里、默认 Agg 无头，退出码与全局状态留在子进程内）；**开窗**（`mpltweak <脚本>` / `launch`）也在**本进程**里跑一遍脚本（`runpy.run_path`，launch.py:885 # runpy.run_path），用的是**交互后端**（QtAgg 优先、TkAgg 兜底，launch.py:176-191 # _detect_backend）—— 脚本改过的全局 `rcParams` 留在窗口进程里，关窗即结束；`apply` 只做 AST 改写，除非你要求**重跑验证**（`--write` 后默认重跑一次，`--verify-fast` 只做 `ast.parse`）。

**同一个脚本会被重复执行**：开窗 1 次、每次 `check` / `describe` 1 次、每次 `apply --write` **至少** 1 次
（参数里有"原位写不了"的字段、又要退块时是 3 遍，见 [verify.md](verify.md#写回会跑几遍脚本)）——
所以别把它指向"跑一次会花钱 / 会改数据 / 会发消息"的脚本。

逐命令的实测表（每条都标"会不会跑脚本"）、工具自己的副作用（写哪些文件、写在哪、联不联网、
cwd / `sys.path` / 全局 `rcParams` 怎么处理）见 [exec-boundaries.md](exec-boundaries.md)。

## 三、退出码（口径）

口径收敛成一句话（0.1.11 方案 A，**所有入口一致**）：**`0` 没问题 / 成功；`1` 发现问题（check）；
`2` 跑不起来；`4` 没有可用图形后端**。`2` 覆盖"脚本找不到 / 脚本自己报错 / 顶层未知参数 /
参数文件缺失或不合法 / 工具自身异常"—— 顶层 `mpltweak <脚本>` 与 `launch` / `describe` / `check` /
`apply` / `revert` 给的是同一个数。

**`3` 已退役**：常量（`messages.EXIT_SCRIPT`）保留以免破坏外部 import，但任何路径都不再返回它
（0.1.9 时它在顶层承载"找不到脚本 / 脚本报错 / 未知参数"三件事，现已并入 `2`；3→2 不是软化，
仍是非零失败）。

两点容易踩：**脚本自己的 `sys.exit(N)` 不会成为命令的退出码**（执行在子进程里）；
**找不到脚本时 `apply` 先说"脚本找不到"**，不再先报 `no params:`（脚本是主参数，参数文件是次生产物）。

完整实测表（每个码配实测例子，并写明"只列实测过的组合"）见 [exec-boundaries.md](exec-boundaries.md) 的「退出码（实测）」。

## 四、验证能证明什么、不能证明什么

三层（语法 / 重跑 / 语义）各查什么、`--json` 里的 `layers` 怎么读，见 [verify.md](verify.md)。这里只列**不声称项**：

- **语义层有"不判"的字段**：判不了时 `verified=null`，并把字段列进 `--json` 的 `detail` 的「未判定字段」清单 ——
  这与"没比却说通过"相反，**会显式说出来**。逐条字段清单与原因见 [CHANGELOG](../CHANGELOG.md) 的「已知边界（本版不声称的）」。
- **明确拒绝是能力边界，不是失败**：目标对象静态证不出时（未命名 colorbar 轴、循环里建轴、建轴点与参数条数对不上、载体名不是恰好一次模块层调用 —— 逐条判据见 [verify.md](verify.md) 的判据表；`fig.axes[i]` / `plt.gca()` 与**函数里建图**自 0.1.18 起已经能写）
  不写盘、不插块（`applied=false`、`pending` 非空），并打印可粘贴的手改片段。静态语料全库 **4,427** 份绘图脚本里（0.1.9 静态研究口径；0.1.10 静态筛选普查按 `plot==true` 为 **4,433**），
  这类拒绝（含 fail-closed）共 **7** 例。
- **重合轴（`twinx` / `twiny`）只算一个绘图区**：两块轴**共享同一个位置矩形**（matplotlib 语义：给任一块 `set_position`，另一块立刻跟着变；
  所以拖动它们不会被"撕开"，写回块里也按各自轴名逐条落位 —— 实测 `ax2 = ax1.twinx()` 的脚本，块里能证出 `ax2.set_position(...)` / `ax2.legend(...)` 并写盘成功）。
  已知**不支持**项：两块重合的轴叠在一起时，**Ctrl 加选 / 多选拖拽 / 贴邻吸附无法区分归属**（光标位置与几何对两块都成立），
  这类子项在图形矩阵里是 `skip`（**打印不适用理由**，不是静默通过）；位置也**只能两条轴一起改**（只改其中一条会被另一条覆盖 ⇒ 语义核验不过 ⇒ fail-closed 拒写）。
- **`--verify-fast` 不是"弱一点的重跑"**：它只做 `ast.parse` —— 不重跑脚本、也不证明布局落到了目标图上
  （JSON 里标 `verify_mode: "fast"`、`verified: null`，人读输出也会自己说明）。
- **`--keep-unverified` 是自担风险的档位**：脚本在无头环境跑不通（缺数据 / 依赖 / 需要 GUI）时**默认不保留**这次写回；
  加了它才保留，此时 `verified: null` + 警告，**要自己跑一遍确认**。
- **备份的可逆范围要按作用域看**：`apply --write` 会让脚本旁的 `.tweak_params/` 里同时存在**两份**可回退的备份
  —— ① **固定名** `<脚本>.tweak.bak`（默认 `revert` 用）**首份优先**：只在不存在时创建，之后的写回**不覆盖**它
  ⇒ 回到的是它**建立那一刻**的原文，通常就是你**第一次改这张图之前**的原件（实测：独立进程连续 3 次写回后
  `revert --write` 回到最初原件，不是上一步的中间态）；
  ② **带 pid 的专属副本** `<脚本>.tweak.<pid>.bak`（`revert --first` 用）代表**该次写回之前**，每次写回都新增；
  （首次写回时两份同时建立；之后每次只新增 pid 副本、固定名那份保持不动。）
  `_prune_backups` 保留"最近 5 份 + **最早 1 份**"（裁掉的是**中间**的）⇒ 连续写回很多次后 `--first`
  仍能回到最早那次写回之前；副本写不出来时（典型是 Windows 长路径）`--first` **明确失败 `rc=2`**，
  不会拿固定名备份冒充"最早"。
  备份**恒定落在脚本旁**（`<脚本目录>/.tweak_params/`，锚点是脚本而不是参数文件）⇒ `revert` **不需要**
  传 `--params`。`revert` 自身可逆：覆盖前另存 `<脚本>.revert.bak`。

## 五、语料验证的口径（分母怎么算）

[reliability.md](reliability.md) 的「① 静态层：真实绘图代码语料验证」三条口径，抄在这里以免只看结论：

- **只做静态层**：只做 AST 定位与改写判定，**不执行**语料脚本，也**不再分发**语料本体。
- **通过率 = 真原位写回 ÷ 可原位到达**，不是 ÷ "源码里有这一项"。
- **合计是各族之和，不等于脚本数**（同一脚本的不同族各计一次）。

汇总结论是 **97.8%（3,531 / 3,610）**，且**承诺违约 = 0**（没有任何一行"声称原位写回、字节却没变"）。
逐脚本的 URL / 许可 / sha256 与脱敏判定在 bench 证据包 [tag `evidence-0.1.10`](https://github.com/shdbl/mpltweak/tree/evidence-0.1.10/bench/evidence/0.1.10)（不可变引用：清单 [`manifest.jsonl`](https://github.com/shdbl/mpltweak/blob/evidence-0.1.10/bench/manifest.jsonl) + 逐脚本判定 [`verdicts/scan_full.jsonl`](https://github.com/shdbl/mpltweak/blob/evidence-0.1.10/bench/verdicts/scan_full.jsonl)）。
