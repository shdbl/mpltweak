# 断言表：那 4 个分片日志里的每个 `0` 分别对应哪条判据

命令（4 片并行，seed 就是样本）：

```
& $py tests/test_ast_fuzz.py 250 --offset    0     # 片0：seed   0..249
& $py tests/test_ast_fuzz.py 250 --offset  250     # 片1：seed 250..499
& $py tests/test_ast_fuzz.py 250 --offset  500     # 片2：seed 500..749
& $py tests/test_ast_fuzz.py 250 --offset  750     # 片3：seed 750..999
```

每片跑完都打印 `ALL PASS`（或 `FAILED: N 项 -> [...]`），并逐条打印下面这些判据。
**每一行的"实得 0 例"就是 README 里那个 `0` 的出处** —— 逐条对应如下：

| # | 判据（日志里的原文名） | 报出来的"0"是什么 | 为什么它必须是 0 |
|---|---|---|---|
| 1 | `① 承诺违约=0：改写后 ast.parse 全部通过（250 例）` | `坏语法 0 例` | 工具**承诺**写回，就不能把用户代码写成语法坏掉 —— 这是最高优先的不变量 |
| 2 | `② 只动目标：没有**第三个**字段被顺手改掉` | `越界 0 例` | 用户只改了轴位置，别的字段一个都不许动 |
| 3 | `② 承诺=事实：changes 声称改过的字段必须真改了，反之亦然` | `不符 0 例` | 不许"说了没做"，也不许"做了不说" |
| 4 | `② 安全降级：每例都落在 {原位写回 ｜ block ｜ 拒写} 三者之一` | `第四种 0 例` | **写坏 / 写错位置**是第四种结果 ⇒ 出现即 FAIL |
| 5 | `② figsize **一律不得被越界改写**（t88 修好后零例外；block 追加不算）` | `命中 0 例` | 源码 figsize 不是字面量时必须**拒写该字段**（t88 的修法）；block 通道的**纯追加**不算改写 |
| 6 | `③ 幂等：第二次 apply 必须 0 字节改动（250 例）` | `不幂等 0 例` | 同一输入跑两次，第二次必须一个字节都不动 |
| 7 | `对照形态（plain + figsize 与 pos 都是字面量 ⇒ 缺陷不适用且目标可写）必须能原位写回` | `失败 0` | **防"恒绿"**：对抗形态全部降级也可能是"引擎什么都写不了"，所以必须有一组"本来就该写成功"的对照 |
| 8 | `形态覆盖：每个对抗形态都至少跑到 1 例（9 种）` | `没跑到：[]` | 防"某个形态根本没被生成出来" |
| 9 | `格子覆盖完整（N=36 ≥ 36 ⇒ 每个 (形态 × figsize写法) 都必须跑到）` | `缺 []` | 9 形态 × 4 种 figsize 写法 = **18 个格子**，全覆盖才敢说"扫过了" |
| 10 | `语义抽检（运行期真值）：抽到的 N 例，写回后真跑脚本、目标值确实落到图上` | `失败 0` | **约 10%** 抽样做"写回后真跑脚本、比对目标对象的值"（其余做静态断言，理由见文件头：运行期验证每例 ~0.4 s，全量会把分钟级变成小时级） |
| 11 | `teeth ①..⑤`（5 条，见下） | 全 `OK` | 判据本身必须有牙 |
| 12 | `固定 corpus`：13 条**实测钉住**的可复现样本 | `本轮命中 13 条 / 与实测一致 13 条` | 失败/可疑样本可精确复现（seed 即最小化样本，脚本从 seed 确定性重建） |

## 5 条 teeth（判据的"牙"）

| teeth | 内容 | 期望 |
|---|---|---|
| ① | 勉强替换（写错值） | 判成 `other`/越界 |
| ② | 写坏语法 | `ast.parse` 必须失败 |
| ③ | 顺手改第三个字段 | `other_written` 必须非空 |
| ④ | 端到端：勉强替换 | "承诺=事实"必须报 `False` |
| ⑤ | 端到端：勉强替换 | "安全降级"判据必须报 `False` |

## 怎么自己复算

1. `tools/ast_fuzz_gen.py` 是生成器（**只依赖标准库**、只用 `random.Random(seed)`）；
2. `tests/test_ast_fuzz.py` 是驱动器 + 断言（`--offset` 分片、`--corpus` 只跑固定样本、
   `MPLTWEAK_ASTFUZZ_N` 改样本量）；
3. `ast_fuzz/corpus/corpus.json` 是 13 条钉住的样本（`seed` + 期望 + 理由）；
4. 跑一片约 **3.45~3.52 s/例**（本机实测，随机器变化）⇒ 250 例约 14~15 分钟。
